## 1. 테스트 방법
| 구분 | 방법 | 누가 |
|---|---|---|
| 화면 테스트 (기본) | 개발 서버를 열고 절차대로 직접 조작, 결과를 눈으로 확인 | 사용자 + AI(브라우저 MCP로 같은 절차를 실행·캡처) |
| 상태 확인 | 브라우저 개발자 도구(F12) → Application → Local Storage에서 저장값 확인·수정 | 사용자 / AI |
| 정적 검사 | `npm run build`(타입 검사 `tsc -b` 포함), `npm run lint` | AI |
| 단위 테스트 코드 | 순수 함수(`utils/achievements.ts`, `api/crossref.ts`의 정리·검사 함수)를 Vitest로 코드 테스트 — **조금만** (T1 결정, P098). `npm test` | AI가 작성, 사용자가 읽고 실행 |

- 결과 표기: **통과** / **실패**(→ 오류 기록 번호 E##) / **보류**(아직 구현 전) / 확인한 사람(사용자·AI)과 날짜
- 실패하면 실습지 4.4 오류 분석 순서로: 원인 → 관련 코드·데이터 흐름 → 수정 → 영향 → 다시 실행할 테스트. **실행하지 않은 테스트를 통과라고 쓰지 않는다**
