# 03. 성과 등록·수정 (`/achievements/new`, `/achievements/:id/edit`) + DOI 자동 채우기

> 상태: **확정·구현 완료** (초안 P219 → Q-C1~C8 모두 AI 추천 픽으로 확정 P220, 2026-11-10 → C-1~C-4 P221–P236 → **전체 점검 P237, 3건 수정 P238**). 사용자: 진행하면서 고치거나 기능이 늘면 그때 알려 주기로 — 바뀌면 이 파일에 버전처럼 기록
> 기준 문서: `docs/requirements.md`(FR-10·11·13, BR-02~08·12, EX-01~07·12·16·26, Q1~Q3·Q6), `docs/design.md`(5.5 폼 컴포넌트, 8절 Crossref, 10절 흐름), `docs/test-cases.md`(TC-28·31~38·40~47·52), 시안 `design/mockups/AchievementForm.dc.html`, 체크리스트 4절(03에서 챙길 것)

## 이 페이지의 목적
관리 모드를 켠 랩장이 성과를 **새로 등록하거나 고친다.** 논문이면 DOI만 넣고 "불러오기"를 누르면 Crossref에서 제목·저자·학술지·발행일·링크를 받아 폼에 채워 주고(외부 API 필수 요건), 랩장이 확인·수정한 뒤 저장한다. 불러온 값은 바로 저장하지 않는다(BR-06).

## 미리 확인한 것 — Crossref를 브라우저에서 바로 부를 수 있나 (TC-40, 설계 검토 R6)
2026-11-10 개발 화면에서 직접 호출함 (P219):
- `GET https://api.crossref.org/works/10.1038%2Fnature14539` → **200, 약 1.2초, CORS 문제 없음** — 서버 없이 React만으로 가능
- 받은 값: 제목 `Deep learning` / 저자 3명(`given` + `family`) / 학술지 `Nature` / 날짜 `issued.date-parts = [2015, 5, 27]` / 링크 `https://doi.org/10.1038/nature14539`
- 없는 DOI → **404** (EX-03을 404로 구분 가능)

## 화면 배치 (위 → 아래, 시안 그대로)
1. (관리 모드 띠 — B-4에서 이미 Layout이 그림)
2. **제목 줄** — 작은 글씨 "← 성과 목록"(목록으로) / 큰 제목 "성과 등록" 또는 "성과 수정" / 설명 한 줄 "논문이라면 DOI만 넣어도 제목·저자·학술지·발행일이 채워져요. 불러온 값은 바로 저장되지 않으니, 확인하고 고친 뒤 저장하세요."
3. **단계 안내** — `01 유형 고르기` · `02 DOI 불러오기 (논문만)` · `03 값 확인 후 저장` (보기만, 누르는 것 아님) [시안]
4. **폼 상자** (흰 상자, 둥근 모서리 28px)
   - **유형** \* — 알약 4개(논문·수상·특허·공모전), 고른 것은 검정 [시안]. 키보드로는 라디오 버튼처럼(↑↓←→) [AI 설계 — 접근성]
   - **DOI로 자동 채우기** (유형이 논문일 때만, BR-05) — DOI 칸 + "불러오기" 버튼 + 상태 문장(아래 "동작")
   - **제목** \* / **날짜** \*(`<input type="date">`) / **학술지·학회** / **저자** / **지도교수** / **링크**(`type="url"`, 자리 표시 `https://`)
     - 칸 이름은 유형마다 바뀜 — 시안: 논문 "학술지·학회·저자·발행일", 수상 "수여 기관·대회·수상자·수상일", 특허 "출원·등록 기관·발명자·출원일", 공모전 "대회 이름·참가자·수상일" (Q-C3)
     - **지도교수 칸은 시안에 없음** — 데이터에 있으므로(P150) 저자 다음에 넣는다 [보충]
     - DOI로 채운 칸에는 작은 "자동 입력" 표시 [시안]
   - 아래 버튼: "취소"(흰색) · "저장"(검정)
5. 저장 후 → Q-C1에 따라

## 데이터
- 목록: `useAchievements()` — `addAchievement(input)`, `updateAchievement(id, input)`(이미 2-5에서 만듦: 저장 먼저, 실패하면 `false`)
- 관리 모드: `useAdminMode().isAdmin` (B-4)
- 주소: `useParams()`의 `id` — 있으면 수정, 없으면 등록
- 폼 값: `AchievementInput`(id·isSample 뺀 것, 2-1에서 만듦). 등록은 빈 값 + 유형 논문으로 시작, 수정은 그 성과 값으로 시작
- Crossref: `src/api/crossref.ts` — `normalizeDoi`·`isValidDoi`·`fetchCrossrefWork(doi, signal)` (design 8절)
  - **DOI 정리 함수 합치기** (체크리스트 4절): 팝업의 `utils/links.ts` `doiUrl`·`doiLabel`이 이미 앞의 주소·`doi:`를 떼므로, `normalizeDoi`를 하나만 만들고 둘이 같이 쓴다 (규칙이 어긋나지 않게, EX-26과 같은 이유)

## 동작
- **들어올 때**: 관리 모드가 꺼져 있으면 성과 목록으로 돌려보냄(EX-07). 수정 주소인데 그 번호 성과가 없으면 "성과를 찾을 수 없어요" + 목록으로 가는 버튼(EX-06)
- **입력**: 치는 대로 폼 값이 바뀜(제어 입력). 오류 문장은 "저장"을 한 번 누른 뒤부터 보이고, 그 뒤로는 고치는 즉시 갱신 [시안 + AI 설계]
- **검사(저장할 때)**: 유형·제목·날짜 필수(BR-02, EX-01), 제목·저자·학술지 앞뒤 공백 지움(BR-03), 실제 있는 날짜(BR-04), 링크는 비었거나 `http://`·`https://`만(체크리스트 4절 — 팝업의 `safeLink`와 같은 규칙). 저장 단계의 마지막 검사는 이미 있는 `findRequiredProblem`(EX-26)
- **저장**: 등록 `addAchievement` / 수정 `updateAchievement` → 성공이면 Q-C1, 실패면 폼 위에 "저장에 실패했습니다."(EX-12 — B-5와 같은 문장, P214), 입력값은 그대로
- **취소**: 목록으로, 바꾼 값은 버림 — 떠날 때 경고 없음(Q6, 기말 프론트엔 넣기로)
- **유형을 논문에서 다른 유형으로 바꿈**: DOI 칸이 사라짐(BR-05). 이미 넣은 DOI 값은? → Q-C6
- **DOI 불러오기** (design 10절 흐름):
  1. "불러오기" → `normalizeDoi`로 앞의 `https://doi.org/`·`doi:`·공백 제거(BR-05, AC-13-2)
  2. `isValidDoi` 실패(`10.`으로 시작 + `/` 없음 등) → **요청 없이** "DOI 형식이 아니에요. 10.으로 시작하는 값을 넣어 주세요."(EX-02, 시안 문장)
  3. 상태 "Crossref에서 불러오는 중…", 버튼은 "불러오는 중"으로 바뀌고 눌리지 않음(EX-16, AC-13-6)
  4. 성공 → 받은 값으로 제목·저자·학술지·날짜·링크를 **덮어씀**(design 5.5 — 사용자가 직접 누른 것이므로), "자동 입력" 표시, "불러왔어요. 아래 값을 확인하고, 필요하면 고친 뒤 저장하세요." 지도교수는 Crossref에 없으므로 그대로
  5. 404 → "DOI를 찾을 수 없어요. 값을 다시 확인해 주세요."(EX-03), 폼 값 그대로
  6. 네트워크 오류·그 밖의 실패·시간 초과 → "불러오지 못했어요. 다시 시도하거나 직접 입력하세요."(EX-04)
  7. 화면을 떠나거나 유형을 바꿔 DOI 칸이 사라지면 진행 중인 요청을 취소(`AbortController`)
- **Crossref 값 바꾸기** (design 8절 + 확인 결과): `title[0]` → 제목 / `author[]`의 `given family`(이름만 있는 단체는 `name`) → 저자, Q-C5의 구분 기호로 이음 / `container-title[0]` → 학술지 / `issued.date-parts[0]` → 날짜(빠진 월·일은 01, EX-05) / `URL` → 링크. 응답은 `unknown`으로 받아 필요한 칸만 꺼냄(NFR-01, `any` 금지)

## 컴포넌트 (design 5.5)
- `AchievementFormPage` — 주소로 등록/수정 구분, 관리 모드 검사(EX-07), 수정 대상 찾기(EX-06·Q-C8), 저장 후 이동. 훅: `useParams`, `useNavigate`, `useAdminMode`, `useAchievements`
- `AchievementForm` — 입력칸·검사·저장/취소. 상태: `values`(폼 값), `errors`(칸별 오류), `submitted`(저장을 눌렀는지), `autoFilled`(자동 입력 표시할 칸). 훅: `useState`
- `DoiLookup` — DOI 칸·불러오기·상태 문장. 상태: `lookup: DoiLookupState`. 훅: `useState`, `useRef`(진행 중 요청의 `AbortController`), `useEffect`(사라질 때 요청 취소)
- `api/crossref.ts` — `normalizeDoi`, `isValidDoi`, `fetchCrossrefWork` (+ 단위 테스트: 가짜 응답으로 변환·404·네트워크 오류)
- 수업 밖 기술 (미리 알림): **`fetch`·`async/await`**(외부 API 필수 요건이라 필요), **`AbortController`**(요청 취소 — 안 쓰면 화면을 떠난 뒤 늦게 온 응답이 사라진 폼을 고치려 함), React Router **`useNavigate`·`<Navigate>`**(이미 쓰는 라우터의 이동 기능). 배운 것만으로 하는 대안: 요청 취소 대신 "화면이 살아 있는지" 표시를 `useRef`로 들고 늦은 응답은 무시 — 요청은 끝까지 감
