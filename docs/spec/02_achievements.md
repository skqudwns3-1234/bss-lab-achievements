# 02. 성과 (`/achievements`) — A. 데이터 바탕 / B. 성과 페이지

> 상태: **A 확정·구현 완료** (초안 P148–P149 → Q-A1~A4 결정 P150) · **B 확정·구현 완료** (초안 P189 → Q-B3 설명 P190 → Q-B1~B6 AI 추천 픽 채택 P191 → B-1~B-5 P192–P215 → **전체 점검 P216, 4건 수정 P217**). 실명 표기는 학교 내부망에서만 돌리므로 상관없음(사용자 P150). 이번 초안은 **A. 데이터 바탕**을 자세히 쓰고, B. 성과 페이지(목록·검색·필터)는 A가 끝난 뒤 자세히 쓴다.
> 기준 문서: `docs/requirements.md`(FR-02·04·06·07·14, BR-10~15·19, EX-11·12), `docs/design.md`(2절 타입, 6절 상태, 7절 저장, 9절 계산), `docs/test-cases.md`(TD-A~D).

## 이 단계의 목적
홈의 남은 칸(최근 성과·통계·NEW 알약), 성과 페이지, 등록·수정 폼이 **모두 같은 성과 목록**을 읽고 바꾼다. 그 목록의 **모양(타입) → 처음 데이터 → 계산 → 저장 → 전역 상태**를 아래층부터 만든다. 이 단계는 화면이 거의 없다(확인은 콘솔·개발자 도구·단위 테스트로).

## 쌓는 순서
```
2-1 타입  →  2-2 처음 데이터(샘플 8건)  →  2-3 계산 함수(+단위 테스트)  →  2-4 저장(localStorage)  →  2-5 전역 상태(Context + useReducer)
```

### 2-3 계산 함수 (`src/utils/achievements.ts`, design.md 9절) + 단위 테스트 조금 (T1)
| 함수 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `sortByLatest(list)` | 날짜 최신순, 같은 날이면 id 큰 것 위 (BR-10) | 홈 최근 4개, 목록 |
| `countByType(list)` | 유형별 개수 → 통계 4칸 | 홈 1-6 |
| `getNewestSummary(list)` | 가장 최근 날짜 + 그날 성과 개수 — 한 유형이면 유형 이름, 섞이면 "성과"로 합침 (P161) → NEW 알약 (없으면 `null`) | 홈 1-7 |
| `filterAchievements(list, filter)` | 검색어(제목·저자·**지도교수** — 지도교수는 P157 추가, 대소문자·앞뒤 공백 무시)·유형·연도 | 목록 B |
| `getYears(list)` | 데이터에 있는 연도만, 최신순 | 목록 B 연도 선택지 |
| `nextId(list)` | 최댓값 + 1, 없으면 1 (BR-12) | 등록 |
| `TYPE_LABELS` | `PAPER → 논문` … | 배지·통계 |
| (이미 있음) `padCount`, `formatDate` | 두 자리 숫자, `2026.07.06` | 1-3·1-4에서 만듦 |

- 입력 검사(`validateAchievement`, `normalizeInput`)는 폼 단계(03)에서 만든다
- **단위 테스트: Vitest로 결정 (P157, A안 — 대안 Node 기본 `node --test`와 비교, 수업 밖 도구 — T1)**: `sortByLatest`·`countByType`·`getNewestSummary`·`filterAchievements`·`nextId` 5개 정도. 설치 전에 다시 알림

### 2-4 저장 (`src/utils/storage.ts`, design.md 7절)
- 키: `lab-achievements:items`
- `loadAchievements()`: 값이 없으면 → 샘플 8건 / JSON이 아니면(TD-C) → 샘플 8건 / 배열 안에 형식이 틀린 항목이 있으면(TD-D) → 올바른 것만 (Q7 결정). **어떤 경우에도 앱이 멈추지 않음** (NFR-05, EX-11)
- `saveAchievements(list)`: 성공하면 `true`, 실패(용량 초과·막힘)하면 `false` — 실패하면 화면도 바꾸지 않는다 (EX-12, 설계 검토 R1)

### 2-5 전역 상태 (`src/context/AchievementsContext.tsx`, design.md 6절)
- `useReducer(achievementsReducer, undefined, loadAchievements)` — 처음 한 번만 저장소에서 읽음(lazy init)
- 액션: `add` / `update` / `delete` (`achievementsReducer`는 순수 함수라 2-3과 같이 테스트 가능)
- **저장 먼저, 성공하면 반영**: 다음 목록을 계산 → `saveAchievements` → 성공했을 때만 `dispatch` (EX-12)
- `createContext` + `useContext` → `useAchievements()` 훅으로 홈·목록·폼이 같은 목록을 씀. 내보내는 함수는 `useCallback`으로 고정(목록 줄 `memo`와 짝)
- `main.tsx`(또는 `App.tsx`)에서 `<AchievementsProvider>`로 감쌈
- 관리 모드(`AdminModeContext`)는 성과 수정·삭제 화면을 만들 때(B 이후) 함께

## B. 성과 페이지 — 확정 (P189–P191)
> 기준: FR-06(목록)·FR-07(검색·필터)·FR-08(팝업)·FR-09(관리 모드)·FR-12(삭제), BR-10·11·19, EX-07·08·09·12·24·27, Q4·Q5·Q10, design 5.4·6.2, 시안 `design/mockups/Achievements.dc.html`(목록 보기). 등록·수정 **폼**은 `spec/03`.

### 이 페이지의 목적
방문자는 성과를 **찾아보고**(검색·유형·연도), 줄을 눌러 자세히 본다. 관리 모드를 켠 랩장은 여기서 등록·수정으로 넘어가고, 삭제한다.

### 화면 배치 (위 → 아래, 시안 그대로)
1. (관리 모드일 때) **관리 띠** — "관리 모드 — 성과를 등록·수정·삭제할 수 있어요. 바뀐 내용은 이 브라우저에 저장됩니다." + 깨진 데이터 안내(`notices`, P173). 시안의 "샘플 데이터로 되돌리기" 버튼은 넣지 않음(D3)
2. **제목 줄** — 꾸밈 글씨 `PAPERS · AWARDS · PATENTS · CONTESTS`, 큰 제목 "성과" + 옆에 개수(Q-B2). 관리 모드면 오른쪽에 "성과 등록" 버튼(→ `/achievements/new`, 폼은 03)
3. **검색·필터 줄** — 검색칸(라벨 "제목·저자 검색", 지도교수도 찾음 BR-11) / 유형 칩 5개(전체·논문·수상·특허·공모전, 칩마다 개수, 누른 칩은 검정) / 연도 선택(전체 + 데이터에 있는 연도만 최신순, Q4)
4. **목록** — 얇은 줄(`<ol>`), 최신순(BR-10). 한 줄: 왼쪽 날짜 / 가운데 유형 배지·예시 배지·학회, 제목, 저자(+ DOI) / 오른쪽(관리 모드) "수정"·"삭제"
5. 결과가 없으면 목록 대신 안내 (아래 예외)

### 데이터
- `useAchievements()`의 목록 전체 — **예시 성과도 보임**(목록은 기록 전체, "예시" 배지로 구분 BR-19). 홈 통계·NEW 알약만 실제 성과 기준(BR-15·20)
- 계산은 이미 만든 함수: `filterAchievements`(검색·유형·연도 AND) → `sortByLatest` / 연도 선택지 `getYears` / 칩 개수 `countByType`
- 화면 상태(이 페이지만): 검색 조건 `filter`, 열린 팝업 `selectedId`(홈 1-9와 같은 방식), 삭제 확인 중인 번호

### 동작
- 입력·선택하는 즉시 목록이 바뀜(FR-07). 걸러진 목록·연도 선택지·칩 개수는 상태로 두지 않고 `useMemo`로 계산(design 6.3)
- 줄을 누르면 팝업(`AchievementModal` 그대로, D2). 줄 안의 "수정"·"삭제"는 팝업을 열지 않음
- 관리 모드 스위치는 헤더(시안 위치, D1). 새로고침해도 유지(Q5 — 저장소 키 `lab-achievements:adminMode`)
- 삭제: 확인(Q-B3) → `deleteAchievement(id)` → 실패면 "저장에 실패했습니다."(EX-12, 문장은 P214 사용자)

### 컴포넌트 (design 5.4)
- `AchievementsPage` — 조건·팝업·삭제 대상 상태, 계산(`useMemo`), 함수(`useCallback`)
- `SearchFilterBar` — 검색칸·칩·연도 (받은 `filter`를 그리고, 바뀌면 `onChange`)
