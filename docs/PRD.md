- **한 줄 소개**: 연구실의 논문·수상·특허·공모전 성과를 한곳에 모아, 방문자는 쉽게 찾아보고 랩장은 DOI 입력만으로 간편하게 등록·관리하는 웹사이트
- **배경**: 기말 프로젝트로 만들 연구실 웹사이트(https://github.com/skqudwns3-1234/lab_website)의 **체험판**. 리액트프로그래밍 바이브 코딩 과제(2026-11-02 ~ 11-16)로, 그중 성과 관리 부분을 React만으로 먼저 만들어 본다
- **결과물**: React 웹서비스(`lab-achievements/`) + AI코딩수행결과보고서

## 2. 문제 정의
**사용자가 쓴 문제 (P068, 원문)**
> 현재 연구실 웹사이트가 없어 연구실 인원들의 진행중인 프로젝트 혹은 완료한 프로젝트 or 소논문 or 대외활동 등 다양한 활동들을 저장하고 보관할 공간이 존재하지 않아 불편함을 느낀다 추가로 부원 모집을 할 때 신청자들에게 우리 연구실이 어떤 일을 하고 어떤 연구실인지 보여주기 어려움을 가지고 있다. 추가로 연구실 부원들의 시간표, 파일 올렸을때 프린트 하기 등등 다양한 편의 기능들이 불편함

**문제 나누기와 이번 체험판이 다루는 범위**
| # | 문제 | 체험판 | 기말 |
|---|---|---|---|
| P1 | 연구실 활동(논문·대외활동 등)을 **저장·보관할 공간이 없다** | ✅ 성과(논문·수상·특허·공모전) 아카이브 — 등록·수정·삭제·검색 | 진행 중·완료 프로젝트까지 |
| P2 | 부원 모집 때 **연구실이 무엇을 하는지 보여 주기 어렵다** | ✅ 홈(연구 분야·최근 성과·통계), 소개, 부원 페이지 | 모집공고 |
| P3 | 시간표·파일 출력 같은 **부원 편의 기능이 없다** | — | 부원 로그인 전용 기능으로 |

## 5. 사용자 시나리오
1. **지원자가 연구실을 알아볼 때**: 홈에 들어옴 → 큰 제목과 연구 분야로 무엇을 하는 곳인지 파악 → 최근 성과 카드를 눌러 팝업으로 자세히 봄 → "성과 둘러보기"로 목록에서 관심 분야 검색 → 연락 상자에서 이메일 보내기
2. **랩장이 새 논문을 올릴 때**: 관리 모드를 켬 → 성과 등록 → 유형 "논문" 선택 → DOI 입력 후 불러오기 → 채워진 값 확인·수정 → 저장 → 목록 맨 위와 홈 최근 성과에 나타나고 통계 숫자가 늘어남
3. **랩장이 틀린 성과를 고칠 때**: 성과 목록에서 검색으로 찾음 → 수정 → 값 바꾸고 저장 / 또는 삭제 → 확인 창에서 한 번 더 확인 후 삭제

## 7. 비기능 요구사항
- **반응형**: 760px 이하를 휴대폰 화면으로 봄 (메뉴 접기, 배치 바꾸기)
- **저장**: 브라우저 localStorage — 데이터는 그 브라우저에만 남음 (푸터에 안내)
- **접근성**: 누르는 요소 높이 44px 이상, 키보드 이동 시 포커스 표시, 메뉴·구역 이름(aria) 제공, 색만으로 정보를 구분하지 않음(유형은 글자 배지)
- **디자인**: `docs/design-visual.md` §10 개발용 요약을 따름 (모노톤, G마켓 산스 + Noto Sans KR)
- **지원 환경**: 최신 Chrome·Edge, 휴대폰 브라우저
- **개인정보**: 배포 사이트에 실제 부원 이름·이메일·학번을 넣지 않음 (예시 데이터)

## 8. 외부 연동
- **Crossref REST API** — `GET https://api.crossref.org/works/{DOI}`, 키 없음
- 받는 값: 제목, 저자, 학술지, 발행일, 링크 → 성과 등록 폼에 채움 (바로 저장하지 않음)
- 실패할 때: DOI 형식이 아니면 요청 전에 안내 / 없는 DOI(404)면 "DOI를 찾을 수 없어요" / 네트워크 오류면 다시 시도 안내. 실패해도 직접 입력해서 등록할 수 있어야 함
- 자세한 응답 변환: `docs/design-visual.md` §6

## 10. 기술 스택과 제약
- React 19 + Vite 8 (**TypeScript**, P083–P084에 JavaScript에서 전환), React Router 8 (수업 밖에서 새로 배움), 순수 CSS. 백엔드 없음
- **강의에서 배운 훅을 적재적소에** (교수님 안내, P065) — 억지로 넣지 않고 쓰는 곳마다 이유를 남김 (초안)

| 훅 | 쓸 곳 | 이유 |
|---|---|---|
| `useState` | 메뉴 펼침(사용 중), 폼 입력값, 검색어·필터, 팝업 열림 | 화면에 보이는 값이 바뀌어야 함 |
| `useEffect` | localStorage 저장, 팝업 Esc 키, 팝업 뜰 때 뒤 화면 스크롤 막기 | 화면 밖(저장소·키보드·문서)과 연결 |
| `useRef` | 팝업이 열리면 닫기 버튼에 포커스, DOI 입력칸 포커스 | 다시 그리지 않고 DOM 요소를 가리킴 |
| `createContext`·`useContext` | 성과 목록·관리 모드 공유 | 홈·목록·등록 화면이 같은 데이터를 씀 |
| `useReducer` | 성과 추가·수정·삭제 | 같은 데이터를 바꾸는 방법이 여러 가지라 한곳에 모음 |
| `useMemo` | 검색·필터 결과, 홈 통계·최신 4개 계산 | 목록이 그대로면 다시 계산하지 않음 |
| `useCallback`·`memo` | 성과 목록의 줄(수정·삭제 버튼) | 바뀌지 않은 줄을 다시 그리지 않음 |

- **AI 도구**: Claude Code(데스크톱 앱) + MCP — 브라우저(화면 확인·캡처, 사용 중), 최신 문서 조회(후보), GitHub(배포 단계, 후보). 교수님 안내(P065)
