## 1. 서비스 개요

### 1.1 서비스 정의
연구실의 논문·수상·특허·공모전 성과를 한곳에 모아, **방문자는 쉽게 찾아보고 랩장은 DOI 입력만으로 간편하게 등록·관리**하는 웹사이트. 기말 프로젝트(연구실 웹사이트)의 체험판으로, 서버 없이 브라우저 LocalStorage에 저장한다.

### 1.2 해결하려는 문제 (사용자 작성, P068)
| # | 문제 | 체험판 | 기말 |
|---|---|---|---|
| P1 | 연구실 활동(논문·대외활동 등)을 저장·보관할 공간이 없다 | ✅ 성과 아카이브 | 프로젝트까지 |
| P2 | 부원 모집 때 연구실이 무엇을 하는지 보여 주기 어렵다 | ✅ 홈·부원·지원 안내 | 모집공고 |
| P3 | 시간표·파일 출력 같은 부원 편의 기능이 없다 | — | 부원 전용 기능 |

### 1.3 사용자
| 사용자 | 설명 | 권한 |
|---|---|---|
| 방문자 | 연구실 지원을 고민하는 학생, 외부 연구자 | 모든 공개 화면 보기 |
| 랩장(관리자) | 성과를 올리고 고치고 지우는 사람 | "관리 모드"를 켜면 등록·수정·삭제. 로그인은 없음 (기말에서 로그인으로) |

### 1.4 범위
**포함**: 홈, 성과 목록·검색·필터·자세히 보기, 관리 모드, 성과 등록·수정·삭제, DOI 자동 채우기, 데이터 유지, 부원, 연구실 소개, 404
**제외** — 근거는 `report/01_planning.md` §3 "기말로 미룸"
| 제외 항목 | 근거 |
|---|---|
| 로그인 · 외부인/부원 화면 분리 | 기말 (P054) |
| 프로젝트 · 소식 · 모집공고 페이지 | 체험판 범위 A (P011) |
| 이미지 업로드 · 백엔드 · DB | 체험판은 React만 (P010) |
| 프린터 연동 · 부원 시간표 · 학교 식단 · 웹캠 녹화 | 기말 (P017, P068) |
| 여러 기기·브라우저 간 데이터 공유 | LocalStorage는 브라우저마다 따로 저장됨 |

## 2. 기본 데이터

| link | string | 원문·상세 링크 | 비어 있어도 됨 |
| authors | string | 저자·참여자 (체험판 추가) | 비어 있어도 됨 (Q2) |
| advisors | string | 지도교수 (P150 추가) | 비어 있어도 됨 |

| doi | string | DOI (체험판 추가, 논문만) | 비어 있어도 됨 |

## 10. AI 결과 검토 및 개선 기록
STEP 1 학생 수행 과제용. **사용자가 직접 작성한다.** 지금까지의 기획 단계 결정(P007–P079)은 `report/01_planning.md` ③ 표에 있다.

### 10.1 AI가 도출한 요구사항 중 적절하다고 판단한 항목
- 사용자: "전체적으로 마음에 드는데" (P086) — FR·NFR·BR·EX·AC 구성을 그대로 받아들임. 사용자가 "느낌대로 판단했다"며 이 구성의 장점을 AI가 적어 달라고 요청함 (P088)
- **AI 코멘트 (사용자의 판단 이유가 아니라, 이렇게 했을 때의 장점 정리)**: 기능마다 ID·규칙·예외·수용 기준이 붙어 있어서, 구현할 때 "어디까지 만들면 끝인지"가 분명하고 STEP 4 테스트 항목으로 바로 옮길 수 있다. 또 지금까지 대화로 정한 결정(P번호)이 한 문서에 출처와 함께 모여 있어서, 나중에 왜 이렇게 만들었는지 되짚기 쉽다

### 10.2 AI가 이번에 보충한 요구사항 ([보충] 표시)
목록 줄에서도 팝업 열기, `any` 금지, 공백 제거, 목록 정렬의 두 번째 기준, 검색의 대소문자 무시·AND 조건, 샘플로 되돌리기 전 확인, DOI 형식 기준, 없는 id 화면, 결과 없음의 초기화 버튼, 저장 실패 처리, 우대사항 0개·폼 링크 없음 처리, 불러오는 중 중복 클릭 막기
- 이 중 채택 / 제외할 항목과 이유: 모두 채택 ("나머지는 이대로 하면 될 듯", P086)
- AI가 놓쳤다고 생각하는 요구사항: (없음 — 사용자가 따로 말하지 않음)
