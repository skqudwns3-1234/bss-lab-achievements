## 5. 상태와 데이터 흐름
| 상태 | 위치 | 관리 방법 |
|---|---|---|
| 성과 목록 | AchievementsProvider (전역) | useReducer(추가·수정·삭제·초기화 액션) + useEffect로 localStorage에 저장 |
| 관리 모드 | AdminModeProvider (전역) | useState + localStorage |
| 검색어·유형·연도 | AchievementsPage | useState. 걸러진 목록은 렌더링 중에 계산 |
| 폼 입력값·검증 오류 | AchievementForm | useState (입력값 객체 하나) |
| DOI 조회 상태 | DoiLookup | useState (`idle` / `loading` / `success` / `error`) |

- 흐름: 폼 제출 → `dispatch({ type: 'add' 또는 'update' })` → 성과 목록 상태 변경 → useEffect가 localStorage에 저장 → 목록 화면이 다시 그려짐
- 컴포넌트는 `useAchievements()`, `useAdminMode()` 커스텀 훅으로 전역 상태를 꺼내 쓴다.
- DOI 조회는 [불러오기] 버튼의 이벤트 핸들러에서 호출한다. 사용자 행동에 대한 반응이므로 useEffect로 하지 않는다.
- **대안 (결정 필요)**: Context·useReducer 없이 App에서 useState로 성과 목록을 들고, 각 페이지에 props로 내려준다. 더 단순하고 데이터 흐름이 눈에 잘 보이지만, 페이지가 늘수록 props 전달이 번거로워진다.

## 6. Crossref 연동
- 요청: `GET https://api.crossref.org/works/{DOI}` — 입력값에서 `https://doi.org/` 접두어와 공백을 지운 뒤 호출
- 응답 → 폼 필드

| Crossref 응답 | 폼 필드 |
|---|---|
| `title[0]` | title |
| `author[]`의 given + family | authors |
| `container-title[0]` | venue |
| `issued.date-parts[0]` (빠진 월·일은 01) | achievedOn |
| `URL` | link |
| 입력한 DOI | doi |

- 오류 처리: DOI 형식이 아니면 요청 전에 안내 / 404면 "DOI를 찾을 수 없어요" / 네트워크 오류면 다시 시도 안내
- 불러온 값은 바로 저장하지 않고 폼에 채운 뒤, 사용자가 확인·수정하고 저장한다.
- 코드 위치: `src/api/crossref.js` (호출과 응답 변환), 화면은 `DoiLookup`

## 10. 시각 디자인 (초안, P025 — 사용자 확인 대기)
사용자가 참고 이미지 5장을 줌 (`C:\Users\USER\OneDrive\Desktop\디자인 예시\`): ① Health Lab 랜딩 ② 화장품 브랜드 "the act" ③ 헤드폰 제품 페이지 ④ 검은 배경 에이전시 사이트 ⑤ 랜딩 페이지 섹션 구조도.

**5장의 공통점 (AI 분석)**
- 색: 전부 흑·백·회색만 씀. 브랜드 색이 없음 (5장 중 4장은 밝은 배경, 1장만 검정 배경)
- 글자: 아주 큰 제목 + 작은 본문의 대비, 가는 굵기, 넉넉한 여백
- 버튼: 알약 모양(pill). 검정 바탕 흰 글씨, 또는 흰 바탕에 ↗ 화살표
- 카드: 얇은 테두리나 연회색 바탕의 둥근 카드, 번호(01·02·03)로 섹션 구분
- 구조(⑤): 메뉴 → 큰 제목(hero) → 특징 카드 → … → 행동 유도(CTA) → 정리된 푸터

**적용 판단**
- 방향: **밝은 배경의 모노톤 미니멀** (시안 C에 B의 카드를 섞은 형태). 다크(④)는 5장 중 1장뿐이고, 긴 논문 제목을 읽기엔 밝은 배경이 낫다고 판단
- 그대로 못 가져오는 것: 참고 이미지들은 큰 제품 사진·3D 이미지로 화면을 채우는 홍보용 페이지. 연구실 사이트는 사진이 적고 글·목록이 중심이라, **글자·여백·버튼·카드의 형식만** 가져온다
- 색은 회색조로 하되, 오류(빨강)처럼 기능에 필요한 색만 예외로 쓴다. 성과 유형은 색 대신 테두리 배지 + 글자로 구분
- 참고 이미지처럼 아주 연한 회색 작은 글씨는 읽기 어려우므로, 보조 글씨도 충분히 진하게
- 가는 굵기의 한글 제목은 기본 글꼴(맑은 고딕)로 안 나와서 웹폰트 **Pretendard** 사용을 제안 (CSS로 불러오기만 하면 됨, React 개념 아님)
- 홈: 큰 제목(연구실 이름·한 줄 소개) → 연구 분야 01·02·03 → 최근 성과 카드 3개 → 연락·모집 안내 → 푸터 (⑤의 구조를 연구실에 맞게 줄임)
- 성과 페이지: 긴 논문 제목을 훑어보기 쉽게 **얇은 줄로 나눈 목록형** (홈의 최근 성과만 카드)

- **결정 (P030): A 채택** — 사용자가 "A가 좋아"라고 고름 (이유는 아직 안 물어봄). 홈 시안(Main)의 첫 화면에 A를 넣고, 소개 글·버튼을 제목 아래 왼쪽으로 옮김. 비교용 A·B 시안은 기록용으로 캔버스에 남겨 둠
- **변경 (P031): A·B 모두 제외** — 사용자: "A랑 B 둘다 좀 구린듯 날리고" + 투명한 유리 구슬이 겹친 흑백 사진을 새 참고로 줌. → 홈 첫 화면 배경을 유리 구슬 4개(투명 2, 우유빛 2)로 바꿈. CSS(둥근 모양 + 원형 그러데이션 + 안쪽 그림자 + 가는 테두리)만으로 그림, 이미지 파일 없음. 구슬은 오른쪽에 두고 화면 밖으로 잘리게 해서 사진처럼 크게 보이게 함. 캔버스의 A·B 시안과 B 그림 파일은 삭제
